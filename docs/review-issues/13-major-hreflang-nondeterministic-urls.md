Title: [Major] Hreflang URLs selected non-deterministically from url_rewrite — may pick non-canonical category-nested product URLs

**Severity: Major**

`Model/Hreflang/UrlRewriteFetcher.php:38-56` selects all `redirect_type=0, is_autogenerated=1` rows with **no ORDER BY and no metadata filter**. For products, category-path rewrites (`some-category/product.html`) match those predicates too, so "first row per store wins" (`UrlRewriteFetcher.php:51-53,90-92`) can pick a non-canonical category-nested URL — and the choice is effectively random per store. Hreflang alternates must point at canonical URLs.

The same issue feeds the hreflang sitemap via `fetchAllForType()` (lines 68-96). Additional related problems:

- Disabled-per-store or noindexed products still have url_rewrite rows → hreflang links and sitemap entries can point at 404/noindex URLs (no status check anywhere). Service CMS pages (`no-route`, `enable-cookies`) are also included in the sitemap.
- Paginated category URLs emit alternates pointing at unpaginated page-1 URLs (non-equivalent content pairing).

**Suggested fix:** filter `metadata IS NULL` (root product rewrite) or select deterministically (shortest request_path); join product/category status per store; exclude service CMS pages.
