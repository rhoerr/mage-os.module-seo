Title: [Major] /hreflang-sitemap.xml loads the entire url_rewrite table into memory in a single web request, with no 50k-URL chunking (default ON)

**Severity: Major** (DoS/OOM risk + sitemap protocol violation)

`Model/Hreflang/UrlRewriteFetcher::fetchAllForType()` does a `fetchAll()` over every autogenerated, non-redirect rewrite for products, categories, and CMS pages across all eligible stores (`Model/Hreflang/UrlRewriteFetcher.php:77-84`), and `Model/Hreflang/SitemapGenerator.php:38-54` renders the entire result (products × stores × full alternate set each) into one in-memory XML string per cache miss.

- Product rewrites include category-nested variants, so 100k products × 5 stores can be millions of rows — memory/timeout blow-up on an anonymous-triggerable endpoint.
- The sitemap protocol caps a single file at **50,000 URLs / 50 MB**; no chunking or sitemap index is generated, so mid-size multi-store catalogues produce an invalid sitemap.
- The endpoint is **enabled by default** on any install with 2+ eligible stores (`etc/config.xml:33`, `Controller/Hreflangsitemap/Index.php:45-50`).
- Caching relies on `X-Magento-Tags`/TTL; on built-in FPC the document regenerates per request after expiry, and query-string variations bypass the cache entirely (see the cache-busting issue).

**Suggested fix:** generate the sitemap to files via cron, mirroring core `Magento_Sitemap` (paginated queries, sitemap-index output, served statically). This also resolves the DoS exposure.
